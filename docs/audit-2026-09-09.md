# ClassSync audit — 2026-09-09

Scope: Flutter client, SQLite queue, HTTP adapters, setup/account recovery,
academic modules, platform adapters, Worker/D1, dependencies, local packaging,
and release configuration. Baseline: `c485693`, main, v0.3.8 (0.3.8+16).
Release target: v0.3.9 (0.3.9+17). Remote signing-check commit `f9c6f85`
arrived during the audit and was fast-forwarded without conflicts. No workflow
files were changed.

## Findings and fixes

| Severity | Substantiated issue | Fix and regression evidence |
| --- | --- | --- |
| Medium security | Legacy FCM fan-out included private-account devices, exposing legacy transcript IDs/event metadata. | Scope legacy recipients to NULL account; real D1 delivery test excludes private token. No transcript content was in these payloads. |
| Medium security | A device knowing another registration token could overwrite/delete its registration through legacy routes; account updates could reassign ownership. | Require matching account and device on update/delete; real Worker tests cover legacy and cross-account takeover/deletion. Rejoined Android installations rotate conflicting FCM tokens locally. |
| Medium reliability | Account push failures had no durable retry record; interrupted sends were stranded. | Migration 0006 adds account delivery checkpoints before OAuth/FCM, bounded concurrency, timeout/network retry, stale-send recovery. Real D1 tests exercise failed sends and subsequent delivery. |
| Medium reliability | Reprocessing a completed remote claim short-circuited regeneration. | Page-specific atomic reopening preserves canonical Notion page and excludes competing owners; Worker and pipeline regression tests. |
| Medium reliability | Remote completed jobs newly inserted into SQLite remained discovered because their timestamp was older than the fresh local insertion. | Apply remote state on first insertion; preserve active local leases; database regressions. |
| Medium reliability | Retry/reprocess preparation could clear an active lease; stale failures could overwrite replacement workers. Queued batches leased work long before execution. | Transactional preparation/failure ownership checks; claim only immediately available worker slots. Pipeline tests retain live/replacement ownership. Complete remote claim before clearing local lease. |
| Medium data integrity | Concurrent lecture task extraction replaced the same cache collection and lost one lecture's tasks. | Transaction covers read/merge/write; parallel import regression retains both sets. |
| Medium reliability | Repeated Notion cursors or Fireflies pages could loop indefinitely; malformed continuation could yield incomplete caches. | Bounded pagination with repeat/missing-cursor detection and retryable failure. HTTP adapter regressions. |
| Medium usability | Existing-account setup required API keys/bootstrap token before recovery; finishing recovery could overwrite restored credentials with blank fields. | Welcome recovery entry bypasses key screens, reads saved config without uploading defaults, validates it, preserves restored keys through completion. Phone and full recovery tests. |
| Low release reliability | The incoming signing-check commit used FileInfo.Source in its apksigner fallback, which fails under StrictMode. | Use FullName for FileInfo and Source for CommandInfo; reproduce the property failure and verify both resolution paths against the signed APK. |
| Low correctness | Secure storage trimmed significant leading/trailing whitespace from Portal passwords. | Preserve password bytes; regression verifies round trip. |
| Low QA | Manual transcript dialog allowed repeated submission and let errors escape after closing. | Disable submission while pending, inline validation/error, mounted checks; widget regression exercises pending/error states. |
| Low reliability | Simultaneous initial snapshot writes produced a D1 constraint failure; malformed route escapes caused runtime exceptions; cleanup could delete an identity still referenced by a claim. | Initial insert CAS returns 409, malformed paths return 400, FK-aware cleanup. Real Worker/D1 tests. |
| Medium hardening | Request limits were applied after buffering or absent on JSON routes. | Stream-bound request bodies before routing; oversized request regression. |
| High upstream advisory; limited local exposure | Build-only sharp dependency was below patched 0.35.4. | Pin patched transitive sharp; frozen install and npm audit pass. Worker does not expose sharp image processing. See [upstream advisory](https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c). |

## Validation

- Baseline: 128 Flutter tests and 9 relay tests passed.
- Final client suite: 143 tests passed; handwritten coverage 57.3% (required 50%).
- Flutter analyzer and Dart formatting pass.
- Native Windows integration test builds/runs the actual Flutter desktop app
  with an isolated in-memory database and no integration credentials. It visits
  Overview, Classes, Library, Academic, Sync, Settings; checks empty states,
  import/cancel behavior, and runtime exceptions. Passed.
- Responsive widget QA covers phone and desktop layouts, setup/recovery,
  navigation, connection errors, and library states.
- Final relay suite: 19 tests passed. Tests include a bundled Worker running in Miniflare with real D1 and
  all six migrations, in addition to mocked endpoint tests. Authentication,
  isolation, claims, snapshot races, body bounds, cleanup, and push recovery
  are exercised without production credentials.
- `pnpm install --frozen-lockfile`, TypeScript checking, Worker dry build, and
  `pnpm audit` pass; audit reports zero known advisories. `flutter pub get`
  reports no security advisory warnings. Pub reports advisories through its
  normal resolver ([Dart documentation](https://dart.dev/tools/pub/security-advisories)).
- Reviewed credential storage/redaction, account authentication/encryption,
  parameterized D1/SQLite queries, endpoint ownership, webhook HMAC/replay,
  outbound HTTPS/host checks, model-output validation, retry/error mapping,
  manifests/background scheduling, and release/signing configuration.
- Pattern scans of tracked files and Git history found no matching private
  service-account, GitHub, Notion, or AWS credentials. The PEM marker in the
  Firebase parser is code, not a key. Signing files and local environment files
  remain ignored. This was a pattern scan, not an exhaustive secret detector.

installer uses the repository Inno Setup definition. APK signature/version,
installer/app version, archive integrity, and SHA-256 hashes are checked before

## Limits and rollout

- No Android device/emulator was connected: real Android background execution,
  notification delivery, and token rotation require device QA. APK builds and
  responsive widget tests do not substitute for those OS checks.
- Live Fireflies → Gemini → Notion publication, real recovery-account restore,
  Portal/Moodle authenticated data, and production FCM were not exercised with
  private credentials. Adapters/pipeline use fixtures and failures; existing
  production data was not modified.
- macOS/iOS builds require Apple tooling unavailable on Windows; neither is
  part of the existing local APK/Windows release asset set.
- The cached Firebase Windows SDK was incomplete. A complete official SDK was
  downloaded and required x64 files restored. Disk exhaustion was resolved by
  lossless NTFS compression of the SDK cache; no project/user data was deleted.
  SDK debug-symbol warnings do not prevent native QA.
- Android build tooling emits pre-existing upcoming AGP/Kotlin support and SDK
  XML warnings. No validation bypass was added.
- Deploy migration 0006 and the new Worker separately before using new relay
  behavior. This audit/release does not deploy production infrastructure.
  Existing daily push-retry cadence remains; Fireflies polling is recovery.
- Cloudflare dashboard abuse/rate-limit settings and actual production secrets,
  permissions, and RLS-equivalent deployment state cannot be established from
  this repository. No claim is made that dashboard controls were verified.
